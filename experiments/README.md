# Experiments

Detection quality on public corpora, from one command, with pinned inputs
(thesis RQ1), and the training of the own name model (RQ6). Every table in
`results/` is regenerated by the command that made it; nothing is tuned on
test data.

```sh
uv sync --all-packages --group ner          # GLiNER, for the systems that use it
uv run python -m experiments datasets       # documents and gold spans per split
uv run python -m experiments run --config experiments/configs/rq1-dev.toml
uv run python -m experiments tables experiments/results/rq1-dev.json   # tables only
uv run python -m experiments errors --config experiments/configs/rq6-dev.toml  # error analysis
uv sync --all-packages --group train        # GLiNER and accelerate, for training
uv run python -m experiments train --config experiments/configs/train-smoke.toml
```

`--resource-root` names the directory holding `data/` and `models/` (default:
as for the command line, `resources.resolve_resource_root`). A git worktree
has no `models/` of its own, so from one, name the main checkout. The corpora
and the model are fetched once with `scripts/download.py` and verified
against the catalog.

## What a run does

1. **Loads** each configured split (`datasets.py`) into documents of the
   shared data contract: pages of text and gold spans in our entity types.
   Sentence corpora become page-like texts of 12 sentences.
2. **Detects** with each configured system (`systems.py`), built by
   `core.pipeline.build_detector` and run by `core.pipeline.run_detection`,
   exactly as the command line and the review window run them. A system's
   options only switch what those functions offer: the name model (`none`,
   a catalog GLiNER or NameTag 3 model by id, `gliner` being the default
   one, or a list of two combined by `combine = "union"` or `"agreement"`),
   GLiNER's threshold, labels and distractors, the name filter, propagation,
   and the language (the corpus's, recognised from the text, or none).
   Results keep the model names the config used.
3. **Scores** (`metrics.py`) per type and for any type: precision, recall,
   F1 and F2, with strict (exact span) and partial (any overlap) matching,
   and 95 % bootstrap intervals over documents (seeded). Beside them, leak
   coverage (below): what would stay readable after redaction. Pairs named
   in `compare` get a paired bootstrap of the difference. A system with
   `seeds = [1, 2]` also runs the replicates of its trained model
   (`<model>-s1`, `-s2`, see *Training*) and gets the mean and spread across
   them, and its comparisons are also made seed by seed (`seeds.py`).
4. **Writes** `results/<name>.json` (every score, with commit, machine,
   model and dataset versions, seed) and the same as `<name>.md` and
   `<name>.tex` (booktabs; `\ci` is provided at the top of the file).

Results hold counts and scores only. Documents are named by position, never
by content, so CNEC and UNER, which name real people, cannot leak through a
results file, and the files can be committed.

## Leak coverage

A partial match counts "Jan" found in "Jan Novák" as a hit, yet after
redaction "Novák" is still readable: a partial match is a leak, not a near
miss. Leak coverage measures what redacting every prediction would leave,
per type and for any type. A results file holds it under `coverage` (per
system) and `comparisons[].coverage` (paired differences); the tables show
it in a *Leak coverage* table per corpus. Definitions (`metrics.py`,
`Coverage`):

- **Characters** are those of page text that are not whitespace, so a line
  break inside a name, or the space between two predictions "Jan" and
  "Novák", changes nothing. Offsets are page-local, as everywhere.
- A gold character is **covered** when any prediction in page text covers
  it, whatever the prediction's type and whether or not the corpus scores
  that type: a name tagged as an address is redacted all the same.
- **Residual share**: gold characters no prediction covers / gold
  characters (over the union of the type's gold spans). Lower is better.
- **Hidden whole**: gold spans with every character covered / gold spans
  (the same distinct spans as `found / gold`). Several predictions together
  may hide a span, since redaction removes their union. The benchmark's
  "items found whole" asks for one entity covering the item; for a leak the
  union is what counts.
- **Over-redaction**: characters of the type's predictions outside every
  scored gold span, per 1,000 characters of page text: what the reader
  loses. Like precision, it counts only predictions of scored types, since
  a corpus that does not annotate dates cannot say whether a date is
  personal; a name predicted over an organisation (in the gold, but not
  scored) does count.

Intervals and paired differences use the same resamples as the match
scores. In the paired table a negative Δresidual is an improvement, and p
is that of Δresidual.

The scores are measured on text: redaction boxes every word a span
overlaps (`Page.bboxes_for_span`), so a prediction ending inside a word
leaves less readable on a PDF page than the residual share says. Leak coverage does not replace the
benchmark, which reads the redacted output back.

### Adding it to existing results

Leak coverage needs the predictions, which results files do not keep, so
existing results get it by running their config again. The name models'
output comes from the cache (below), so only the rules and the steps after
the model run:

```sh
uv run python -m experiments run --config experiments/configs/rq1-dev.toml
```

The last `rq1-dev` run answered all of GLiNER's 202, 134 and 153 windows
from the cache (`cache` in the results file: no misses) and spent under
0.3 s on detection per system and corpus; reading the corpora and the
1,000 resamples come on top. The model is loaded only on a miss, which a
changed model input (window text, labels) causes; misses are counted under
`cache`. The rerun scores with today's detection code, so other scores may
move where detection changed since the file was written: compare with
`git diff experiments/results/`. `python -m experiments tables <old>.json`
renders a file without coverage exactly as before.

## Datasets

| id | splits (role) | language | scored types |
|---|---|---|---|
| `cnec-2.0` | `train` (train), `dtest` (dev), `etest` (test) | cs | person, address, phone, email, url |
| `uner-sk-snk` | `train` (train), `dev` (dev), `test` (test) | sk | person |
| `redact` | `sample` (dev), `test` (test) | cs | person, email, phone, address, date, birth_number, id_number |
| `openpii-1m-cs`, `-sk`, `-en` | `train` (train), `dev` (dev), `test` (test) | cs, sk, en | person, address, email |
| `name-forms-cs`, `-sk` | `dev` (dev), `test` (test) | cs, sk | person, with recall per name form |
| `heldout-cs`, `-sk` | `dev` (dev), `test` (test) | cs, sk | person, address, email, phone, birth_number, date, bank_account, iban; recall per name form |

Only the types a corpus annotates are scored on it; any other prediction is
counted under `unscored_predictions`. CNEC and UNER also keep their
organisations in the gold, never scored: training teaches the name model's
`organization` distractor from them. The full mapping from each corpus's
types to ours, and what is left out and why, is in the `datasets.py`
docstring. In short: CNEC persons are the outermost `P` containers plus first
names and surnames standing alone (not inhabitants, mythological persons or
titles); UNER persons are `PER`; REDACT is read for its Czech records only
(it has no Slovak), and a full name nested over its first name counts once.
Its `sample` split is the 1,000-record sample file; `test` is the full
release's Czech records that the sample does not repeat.
OpenPII 1M is one catalog entry read as one dataset per language. It has no
test split, so its validation split is cut in two by a hash of each record's
uid: `dev` for tuning, `test` reserved. Its identifiers and phone numbers are
not scored: they are invented without checksums or a numbering plan.

The name-forms sets and the held-out set are generated in code
(`name_forms.py`, `heldout.py`), not downloaded: no files, no catalog
entry, and their version is the generator's. See *Name forms* and
*Held-out synthetic set* below.

UNER keeps each sentence as written (`# text`) and groups pages by source
document. `text = "tokens"` on a dataset entry builds the text instead from
tokens joined by spaces, cut into pages across document boundaries: how the
2026-10-02 sweep did it.

## Name forms

`name-forms-cs` and `name-forms-sk` are short generated texts naming invented
people (common first names and surnames combined arbitrarily) in controlled
forms, to measure which forms of a name a system misses. The benchmark finds
names of two words 80 of 81 times but names of one word 5 of 16
(`docs/findings.md`); this set says which forms those are, at a size that
runs in minutes.

- **Forms** (each gold span is tagged): a full name in each of the seven
  cases, a surname after pan/paní/pane in each case, a surname alone in a
  later sentence, a first name alone, a nickname (Honza, Báro), the
  possessive of a surname or first name (Novákova, Janin), English names in
  Czech text; also the declension class of the name (Novák, Beneš, Hájek,
  Svoboda, Novotný, Nováková, Novotná, Jana, Marie, ...) and the gender.
  Slovak has no vocative and no English names here. Names are declined by
  hand-written rules (`declension.py`), tested against forms written by hand.
- **Texts naming nobody**: 8 Czech and 4 Slovak per split, with capitalised
  role nouns ("Kupující", "Žadatel"); predictions in them are false alarms.
- **Size**: each template is filled 12 times. Czech dev: 64 templates, 776
  texts, 960 names (24 per form and case); Slovak dev: 24 templates, 292
  texts, 360 names (12 per form and case). Test has as many texts (948
  Czech and 348 Slovak names).
- **Splits**: `dev` and `test` share no name and no template. `test` is
  read only with `stage = "final"`.
- **Evaluation only.** A generator of training data must not reuse these
  templates: a model trained on them would be scored on its own training
  texts (CLAUDE.md, *Testing*).

Besides the standard tables, the run writes recall per form, form and case,
case, declension class and gender, strict and partial (`phenomena.py`), with
bootstrap intervals over texts, and the false alarms in texts naming nobody.
Twelve texts of one template share their wording, so the intervals are
narrower than resampling templates would give; read them as a guide, not a
test. Changing a template or a name changes the texts: bump
`NAME_FORMS_VERSION` and the digests pinned in `tests/experiments/test_name_forms.py`.

```sh
uv run python -m experiments run --config experiments/configs/name-forms-dev.toml \
    --resource-root /path/to/main/checkout
```

## Held-out synthetic set

`heldout-cs` and `heldout-sk` are the held-out synthetic set of RQ6's final
test: short documents generated from templates written for this set alone
(`heldout.py`). The same author writes the training generators and this set,
so it flatters a model trained here; it is reported apart from the public
test sets ("home advantage").

- **Documents**: letters, contracts, forms, e-mails and minutes, 5 to 14
  lines each (about 90 words in Czech, 70 in Slovak), naming invented
  people (first names and surnames combined arbitrarily, relatives sharing
  a surname) with their addresses, birth numbers, dates of birth, phones,
  e-mail addresses and bank accounts (Czech account numbers, Slovak IBANs).
  Birth numbers, account numbers and IBANs get their check digits from
  `heldout.py`'s own arithmetic; the tests cross-check them with the core
  validators. Organisations, towns, dates of
  contracts and amounts are text, not gold.
- **Forms** (each person span is tagged, as in the name-forms set): `form`
  (full, title-surname, later-surname, lone-surname, first-name, nickname,
  surname-possessive, first-name-possessive, initial, surname-first), `case`,
  `form-case`, `class`, `gender`, plus `context` (role-noun: a role or kinship
  noun right before the name or after its comma, "svědkyně Nováková",
  "Jan Novák, jednatel"; degree: "MUDr."; label: "Pacient: "; else plain) and
  `kind` (the document kind). A surname alone is *later* when the document
  named the person before, *lone* when it did not. Templates lean on the
  forms models miss on dev: a surname alone in a later sentence, mostly in
  the nominative, possessives, nicknames, names next to role nouns.
- **Size**: `test` has 24 Czech and 16 Slovak templates, each filled 8 times
  with other people, plus 4 Czech and 3 Slovak documents naming nobody
  (capitalised role nouns only): 196 Czech documents with 1,312 person spans
  (224 of them a later surname in the nominative) and 131 Slovak documents
  with 776 (128). `dev` has 4 Czech and 3 Slovak templates of its own,
  filled 4 times, plus one document naming nobody each (17 and 13
  documents): enough to look at the generator's output and to check that
  the pipeline reads it, never to tune on. Minimum counts per form and
  context are asserted in `tests/experiments/test_heldout.py`.
- **Splits**: `dev` and `test` share no template and no name; neither shares
  a name with the name-forms set or a person of the benchmark. `test` is
  read only with `stage = "final"`, and the set has no train split, so
  `experiments train` refuses it too.
- **Disjoint templates.** A test compares the word 5-grams of every template
  line (slots and benchmark marks read as one placeholder word, gender
  alternatives as their masculine text) with every string constant in the
  Python modules of `experiments/`, `benchmark/` and `scripts/` and with the
  benchmark's documents, and with the other half of the set. Any shared
  5-gram fails it. Shorter shared phrases ("S pozdravem", "Od: … <…>") are
  allowed: they are conventions, not templates.
- **Rule for training data**: no generator of training data may reuse these
  templates or their sentences. A generator written as Python in those
  directories is checked by the test above without further work; one kept
  elsewhere adds its directory to the test.

A run writes the standard tables and, as for the name-forms set, recall per
form, case, declension class and gender, here also per context and
document kind (`phenomena.py`). No config reads `test` yet: the final
config adds it with `stage = "final"`.

Changing a template, a name or a value list changes the documents: bump
`HELDOUT_VERSION` and the digests pinned in `tests/experiments/test_heldout.py`,
and record why in the journal. After the final test has read `test`, it is
never changed again.

## FUNSD scans

`python -m experiments funsd --work outputs/funsd --engines onnxtr,kraken` reads
FUNSD's 50 test forms (real noisy scans, English) with each OCR engine, runs
detection, redacts, and runs the leak check; `experiments.funsd` describes the
ground truth. Scoring is the scanned benchmark's (`benchmark.ocr_run.score_scan`),
but false alarms are counted and never written, since the forms name real
people. The table goes to `results/funsd-test.md`; the work directory receives
the scans and redacted copies and must stay out of git.

FUNSD labels no personal data. An answer linked to a question naming a person,
phone or address field is an item of that type: 103 persons, 69 phones and 10
addresses on the test forms. These are derived, not annotated.

## Training

```sh
uv run python -m experiments train --config experiments/configs/train-cs-sk-ce.toml \
    --resource-root /path/to/main/checkout
```

fine-tunes GLiNER (`train.py`) on this machine's Apple GPU (`device =
"mps"`) or CPU, from a config naming the base model, the train splits and
how many examples to draw from each (seeded), steps, batch size, learning
rates (encoder, and GLiNER's span and prompt layers), warm-up, weight decay
and the loss: `ce` (binary cross-entropy per span and label, since GLiNER
scores each pair with a sigmoid), `focal` with `focal_alpha` (the weight of
the positive pairs; above 0.5 favours recall) and `focal_gamma`, or
`weighted`, this repository's recall-weighted loss (`loss.py`): the term of
the positive pairs is multiplied by `positive_weight`, so a missed name
costs that many equally confident false alarms, and `negative_focus`
optionally fades out the negatives the model already rejects, never the
positives. `positive_weight = 1` without focus is `ce`, value for value.
`loss.py` also records how gliner computes its loss. The config module
docstring lists every key. Only train splits are read for training
and only development splits for scoring; anything else is refused.

1. **Examples** (`examples.py`): each split is loaded as the evaluation
   loads it and its pages are cut into examples of at most 150 GLiNER
   tokens (the detector's window), never inside a gold span and after a
   line break where one falls in the second half. Spans cover whole tokens.
   Each example is prompted with the detector's labels (`person`, `street
   address`, the `organization` distractor) that its corpus marks
   throughout, so UNER is not asked for addresses or OpenPII for
   organisations. An example holding a span wider than the model's 12
   tokens is left out and counted.
2. **Training** runs gliner's Trainer, seeded by the config (example order
   too); the loss is logged every `logging_steps`.
3. **Storing**: the weights go to `<resource root>/models/<model>/` beside
   the base model's `gliner_config.json`, and the model is listed in
   `<resource root>/models/trained.json` with the SHA-256 of each file, its
   base, data and licences. From then on `rules+<model>` runs in `experiments
   run`, the benchmark, the CLI (`--name-model <model>`) and the window,
   whenever that root is the resource root. It is never downloaded:
   `scripts/download.py verify` checks it, `fetch` refuses it.
4. **Scoring**: the stored model is loaded back through the root's catalog
   and `rules+<model>` is scored on the `[evaluate]` splits, as `experiments
   run` would (its predictions land in the cache, so a later run of
   `rq6-dev` reuses them).
5. **Writes** `results/<name>.json` (commit, machine and chip, package
   versions, seed, config, base model and data versions, example counts,
   the loss log, seconds per step, the model's catalog entry, the scores)
   and `results/<name>.md` (the score table).

Weights trained on CNEC or UNER hold real public names: they stay under the
resource root, are never committed or published, and their entry says
`real_personal_data`. On the M4 Pro a step of 8 examples takes about 1.4 s and
batches of 16 train 1.26 times as fast (`docs/findings.md`), so `train-cs-sk-ce`
(2,000 steps of 16) takes about an hour and a quarter, plus about a quarter of
an hour of scoring.

### Seeds

One run per setting cannot tell the loss's effect from training noise: the
bootstrap resamples documents, not training runs. `--seed N` trains the same
config again with seed `N`, stored as `<model>-sN` with results
`results/<name>-sN.json` (`seed` and `replicate` record it):

```sh
for seed in 1 2; do
  uv run python -m experiments train --config experiments/configs/train-cs-sk-weighted.toml \
      --seed $seed --resource-root /path/to/main/checkout
done
```

The seed draws the OpenPII examples, orders all of them and seeds the
trainer, so one seed always gives the same examples in the same order, and
replicate `sN` of two losses saw the same data. A run config lists the
replicates with `seeds = [1, 2]` on the system of the config's own run
(`rq6-loss-dev.toml`); `results/<name>.md` then adds *Across seeds* (mean ±
standard deviation per system) and *Seed by seed* (the difference per seed,
and on how many seeds F2 rose).

### Another device

`--device cpu` trains a config written for the Apple GPU on a machine
without one, under the same name and model id; `--device mps` does the
reverse. The results keep the file's text under `config` and record the
device used under `machine`. On a 4-core laptop CPU (i7-8550U) a step of
16 took 28 s against about 2 s on the M4 Pro's GPU
(`results/train-cs-sk-weighted-w5.json` against its replicates), so a run
takes about 15 hours; the two devices do not compute bit for bit alike, so replicates of
one setting belong on one device.

### Tuning the weight

`positive_weight` is tuned on development data only, against person F2
(partial match) on the development splits, the main metric of the
evaluation contract; the test splits are read once, with the chosen weight.
Each weight is a copy of `train-cs-sk-weighted.toml` with its own `model` id
(`-w5`, `-w10`), trained with three seeds and scored beside `ce` and `focal`
by `rq6-weight-dev.toml`. In a model that fits its data perfectly a weight `w` acts as
a lower threshold (`t / (w(1 - t) + t)` instead of `t`: 0.125 instead of
0.3 for `w = 3`), so `ce` is also scored at that threshold: the loss
contributes only what beats `ce` at the matching threshold.

## Cache

Each name model's raw output is cached under
`<resource root>/.cache/experiments/<model>@<version>/<dataset>@<version>/<split>.json`,
keyed by a hash of the model input (GLiNER: window text, labels, decoding
mode; NameTag 3: a page's tokens), so a changed text or prompt misses instead
of answering wrongly. The files hold offsets, labels and scores, no text. A
trained model's version is the SHA-256 of its weights, so a model trained
again under the same id starts a new cache; the scores `train` writes come
from the GPU, a later `run` on the CPU reads them from the cache. GLiNER is
asked at threshold 0.1 and each system filters upwards, which equals asking at the higher threshold: flat
decoding is greedy, highest score first (checked on 123 CNEC windows). A
system with a threshold below 0.1 (cross-entropy at the thresholds matching
weights 5 and 10) reads a second cache asked at 0.02, in `<split>@floor0.02.json`
beside the first, so filling it never rewrites the file other runs read. Every
step after the model runs again on every run. A rerun from a warm cache takes
seconds and does not load the model. Systems combining two models reuse
each model's cache, so a union or agreement costs no extra inference.

## Error analysis

Scores say how much a system misses; the error analysis says what kind of
names it misses and what it wrongly flags, per corpus and system:

```sh
uv run python -m experiments errors --config experiments/configs/rq6-dev.toml \
    --resource-root /path/to/main/checkout
uv run python -m experiments errors --config experiments/configs/name-forms-dev.toml \
    --resource-root /path/to/main/checkout --examples outputs/error-examples
```

It reads any run config and runs its systems exactly as `run` does (same
loaders, same `core.pipeline` path, same name model cache), then writes
`results/<name>-errors.json` and `.md` (`errors.py`). A warm cache answers
every model input, so after `run` on the same config and commit it takes
seconds per system and loads no model; `cache.misses` in the file says
whether it did. Persons and addresses are analysed, on the corpora that
score them.

**Misses** are gold spans that no prediction of their type overlaps (*not
found*: exactly what partial-match recall misses) and gold spans overlapped
but not covered whole (*found only in part*: the rest stays readable).
Each gold span falls into categories computed from its own text and its
line, the same for every system:

| category | the gold span |
|---|---|
| `words=1`, `words=2`, `words=3+` | has this many words, split at whitespace |
| `title` | follows a title or honorific (Ing., Mgr., pan, paní, pane, pán, Mr., ...) or starts with one |
| `sentence_start` | starts its line, or follows `.`, `!`, `?` that does not end a title or an initial |
| `after_label` | is the value of a form line "Label: value" (one to four words before the line's first colon) |
| `all_caps` | has at least two letters, all upper case |
| `hyphen_apostrophe` | holds a hyphen, en dash or apostrophe (double surnames, O'Brien) |
| `diacritics` | holds a letter outside ASCII |
| `initial` | holds a one-letter initial ("J. Novák") |

Per category the table gives the misses, their share of the system's
misses, and the **miss rate**: misses in the category / gold spans in the
category, with a 95 % bootstrap interval over documents (the run's seed
and resamples). Compare systems by the rate: the share depends on how much
else a system misses. Misses that a prediction of another type overlaps are
counted on their own: they are redacted all the same.

**False alarms** are person or address predictions that overlap no gold
span of their type (what partial-match precision counts against). Their
categories: `words=*`, `title`, `sentence_start`, `after_label` and
`all_caps` as above, and `capitalised_word` (one capitalised word, not all
capitals), `role_noun` (starts with a role noun of `detect/roles.py`'s
lists for the corpus's language), `organization` (overlaps a gold
organisation; CNEC and UNER mark them) and `other_type` (overlaps a gold
span of another type). The rate is false alarms / predictions in the
category.

The definitions are exact in the `errors.py` docstring. A category is a
structural cue, not a cause: `sentence_start` misses say where a model
fails, not why. The results hold counts and rates only. `--examples DIR`
also writes up to five example spans per category, with 40 characters of
context, for the corpora the catalog does not mark as naming real people
(REDACT, OpenPII, the name-forms sets), never for CNEC or UNER; the folder
must be ignored by git and outside `results/`, or the command refuses.

## Leak check breakdown

```sh
uv run python -m experiments leaks scan.pdf --out leaks/ --engines onnxtr --system rules+gliner
```

`--system` is `rules` or `rules+<catalog name model>`, as in the benchmark.

Loads one PDF with each OCR engine, detects, redacts and runs the leak check,
then counts why it failed (`leaks.py`): reports grouped by layer, page and
text, each text named by a hash salted afresh on every run, with its length
and shape, the entities behind it by source and type, where each OCR
occurrence lies (beginning a longer word, inside a word, across words, a
word of its own read the same or differently at ingest) and, for a word
under a box, its share of black fill and untouched ink. It prints no text and
no file name, so it can run on a real scan; its output stays out of the
repository, since it describes one person's document.

## NameTag 3 against upstream

`python -m experiments.nametag_reference export|compare --model <id> --out <dir>`
checks that the project's NameTag 3 code (run without Keras) labels as
upstream `nametag3.py` does: `export` writes the benchmark's synthetic
documents, cut by the model's own UDPipe tokenizer, and a model directory
upstream loads offline; upstream tags them in its own environment (the
module docstring has the command); `compare` counts tokens and entities on
which the two differ. On 2026-10-10: no difference, Czech model 5,733 tokens
and 881 entities, multilingual 5,659 tokens and 230 entities.

## Tests

`tests/experiments/` runs the loaders, metrics, cache and a whole run on
synthetic text in each corpus's format, with a stand-in model, and checks
the name-forms declension against forms written by hand. The
`dataset`-marked tests count spans in the real corpora; they look under the
repository's `data/`, or under `ANONYMIZER_RESOURCE_ROOT`:

```sh
ANONYMIZER_RESOURCE_ROOT=/path/to/main/checkout uv run pytest -m dataset tests/experiments
```
